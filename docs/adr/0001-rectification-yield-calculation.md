# ADR-0001: 整形良率计算

## 状态
已确认 (grilling session, 2026-07-30)

## 背景
用户希望量化"如果对 NG 产品进行物理整形修复"后能挽回的良率。

## 决策

**判定规则**:
- 一条 SN 被判为 NG。
- 检查该 SN 所有为 NG 的 FAI 列。
- 如果这些 NG FAI 全部在**整形白名单** [FAI312, FAI313, FAI314, FAI315, FAI316, FAI317, FAI318, FAI319, FAI320, FAI321, FAI322, FAI323, FAI324, FAI325, FAI326, FAI327, FAI344, FAI346, FAI347, FAI348] 内（白名单 FAI 名称需匹配 `_T`/`_Z` 等后缀变体），则该 SN 是**可整形 SN**。

**挽回率**:
- 预计整形后挽回的 SN 数 = 可整形 SN 数 × 86%
- 预计整形后良率 = (原 OK 数 + 可整形 SN 数 × 86%) / 总 SN 数

**示例**:
- 286K 行中，5K 条 NG
- 5K NG 中，2K 条可整形
- 预计整形后 NG = 5K - 2K × 86% = 5K - 1.72K = 3.28K
- 预计整形后良率 = (281K + 1.72K) / 286K = 98.8%

## 报表呈现
- 出现在"回归后"日良率报表中 (与回归后良率并列)
- 明确区分"回归后良率" vs "回归后预计整形后良率"

## 报表呈现 (ADR-0001 补充)

**位置**: 在 `get_report_bytes_post()` 输出的 `日良率` Sheet 同表加 3 列:
- `预计整形NG` (列 6): 预计被救回前 NG 数
- `预计OK` (列 7): OK + 可整形 × 86%
- `预计良率%` (列 8): (OK + 可整形 × 86%) / 总数

**未在 Sheet 中体现**: 整形前/后 OK 数量单独列 (避免列太多, OK 数可由其他列推算)

**保持区分**:
- 列 1-5 是**回归后**良率 (已有)
- 列 6-8 是**回归后预计整形后**良率
- 列名加 "预计" 前缀明确区分
