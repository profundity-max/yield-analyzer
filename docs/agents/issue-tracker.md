# Issue Tracker

**Type**: GitHub Issues

**Repo**: `yield-analyzer` (local repo, push to GitHub remote when ready)

**CLI**: Use the `gh` CLI (`gh issue create`, `gh issue list`, etc.)

**PRs as a request surface**: off

Skills that read/write issues:
- `to-tickets` — creates issues from tickets
- `triage` — reads/updates issue labels
- `to-spec` — publishes specs as issues
- `implement` — reads tickets from issues
- `wayfinder` — creates investigation tickets
