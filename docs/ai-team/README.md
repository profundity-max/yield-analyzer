# Web小程序开发 AI Team 使用说明

## 推荐拓扑

主线程承担 `integrator`，负责最终决策和交付。子智能体按任务启动：

| 角色 | 用途 | 典型启动时机 |
|---|---|---|
| `planner` | 需求拆解、依赖、文件所有权、验收标准 | 每个跨模块任务开始时 |
| `backend` | 后端、API、数据库、业务逻辑、后端测试 | API 契约冻结后 |
| `frontend_ui` | UI 设计、页面实现、响应式、交互状态 | API/UI 契约冻结后 |
| `qa` | 独立测试、边界、回归、缺陷报告 | 可提前写计划，实现合并后执行最终验证 |

不要同时启动全部角色。推荐按“计划 → 契约冻结 → 并行实现 → 测试 → 集成”五步执行。

## 完整团队调用提示词

```text
在这个项目中启动 AI Team，你作为主线程的 integrator / Team Lead，拥有最终决策权。

本任务明确允许你使用子智能体。请严格按下面流程执行：

1. 阅读项目 AGENTS.md、docs/ai-team/README.md 和实际可执行脚本，确认需求基线、约束和验收标准。
2. 启动 planner 子智能体，让它输出任务图、依赖、负责人、文件所有权、并行边界和验收标准。
3. 你审核 planner 的结果，冻结 API、数据模型、错误码、UI 契约和文件所有权。
4. 契约冻结后，按任务需要并行启动 backend 和 frontend_ui：
   - backend 只修改分配的后端文件
   - frontend_ui 只修改分配的前端、样式和前端测试文件
5. 合并实现后启动 qa 做独立测试和回归验证。qa 可以提前编写测试计划。
6. 你负责审查全部改动、解决接口不一致、执行最终验收，并完成版本、变更说明 Excel 和 Git 提交。

约束：
- 子智能体不得写入同一文件。
- 子智能体不得撤销其他人的改动。
- 子智能体不得继续创建子智能体。
- 没有实际执行过的测试，不得标记为通过。
- 发现需求冲突或重大歧义时先停止并汇报，不要擅自猜测。

输出：
- 已实现功能
- 改动文件
- 验证命令与结果
- 验收标准逐项结果
- 未解决风险
- 版本与 Git 信息
```

## 单角色调用

### 只做任务规划

```text
只启动 planner 子智能体。不要修改产品代码。请输出任务图、依赖、文件所有权、并行边界、待确认问题和验收标准。
```

### 只做后端

```text
只启动 backend 子智能体处理这个任务。先确认 API 契约，再实现分配的后端文件，并报告改动、测试命令和测试证据。
```

### 只做前端 UI

```text
只启动 frontend_ui 子智能体。先给出页面结构、状态设计和响应式方案，再实现分配的前端文件。不要修改后端代码或已有 API 契约。
```

### 只做测试

```text
只启动 qa 子智能体做独立验证。不要修改产品代码。对每个结论提供命令、日志、截图或可复核证据，并区分已验证、未验证和阻塞项。
```

### 继续原角色

```text
继续使用刚才的 backend 子智能体修复 qa 报告的缺陷，不要新建 agent。只允许修改原分配文件，完成后重新运行相关测试。
```

## 主线程管理提示词

查看状态：

```text
列出当前所有子智能体、角色、状态、负责文件、已完成工作和阻塞问题。
```

收敛范围：

```text
暂停新增任务。先关闭已完成子智能体，保留主线程；然后汇总当前改动、未完成项和风险。
```

最终验收：

```text
作为 integrator 执行最终验收：逐项检查验收标准，运行完整测试，审查 Git diff，确认版本和 Excel 变更说明，最后给出已验证、未验证和风险清单。
```

## 模型与并发

`.codex/config.toml` 默认最多同时运行 2 个子智能体。本地模型代理稳定后可增加，不建议为了“看起来并行”同时启动所有角色。

角色文件默认继承主线程模型。只有在确认模型名称、上下文容量和本地代理并发能力后，才为单个角色指定不同模型。

## 配置验证

```bash
codex doctor --summary
codex features list | rg 'multi_agent|agent_message'
```

修改配置或角色文件后，新开一个 Codex 任务/线程再调用团队。
